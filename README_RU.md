# Gift Offer 1.6.2 — автоматизация чатов, офферы и журналы

Telegram-бот по референсам: `.buy`, карточка подарка, принятие и отклонение, Stars/Gram как цена предложения, четыре языка. **Ручная настройка Telegram ID убрана.** Владельца чата, продавца и покупателя бот определяет из данных Telegram. Для запуска обязательна только переменная `BOT_TOKEN`.

## Запуск

1. Создай своего бота у [@BotFather](https://t.me/BotFather) командой `/newbot`. Включи **Secretary Mode**; в старых интерфейсах он может называться Business Mode.
2. Распакуй архив. В корне должны находиться `bot.py` и папка `gift_offer`. Нужен Python 3.11 или новее, сторонние пакеты не требуются.
3. Скопируй `.env.example` в `.env` и вставь токен в `BOT_TOKEN`. Остальные настройки уже имеют значения по умолчанию.
4. Запусти `python bot.py`. Открой своего бота и отправь `/start`.
5. Подключи бота к своему аккаунту через **«Автоматизацию чатов»** в настройках Telegram. Разреши доступ к нужным личным чатам, ответы и **удаление сообщений** (`can_delete_all_messages`). Право удалять только сообщения самого бота не позволяет удалять команды владельца. В старых клиентах раздел находится в Telegram Business.
6. Для админ-доступа отправь **`/ClezzyKryt` в личный чат с ботом** с этого же подключённого аккаунта. Откроется админ-панель.

```bash
cp .env.example .env
python bot.py --check
python bot.py
```

Токен хранится на сервере, не в переписке. Коды входа, пароль Telegram и сессия аккаунта не нужны. `--check` проверяет настройки без запросов в Telegram. Бот не регистрируется и не запускается в Telegram автоматически из архива: нужен токен твоего бота.

## Админка по /ClezzyKryt

При первой успешной активации промокода админ-доступ закрепляется за аккаунтом, который уже подключил бота через Telegram. Он сохраняется в SQLite после перезапуска. Другой пользователь не сможет забрать этот доступ повторным вводом того же промокода. Пересланный промокод не активирует доступ.

Повторный ввод промокода администратором открывает панель. Команды и кнопки работают только в личном чате администратора с ботом:

| Команда | Что показывает |
| --- | --- |
| `/admin` | Статистику и кнопки журналов |
| `/logs` | Все записанные события |
| `/visits` | Кто отправил `/start`: имя, @username и время |
| `/transfers` | Заявления о передаче/получении NFT и доступные служебные события Telegram |

В панели также есть журнал офферов. Кнопки «Старее» и «Самые новые» переключают страницы. Время показано по Москве. Записи содержат ссылки на профили участников и на подарок; числовые ID вручную вводить не нужно.

## Что записывается

| Событие | Данные в журнале | Источник |
| --- | --- | --- |
| Запуск бота | Имя, @username, время | Команда `/start` |
| Создание и решение по офферу | Участник, подарок, цена, время | Команда и кнопки оффера |
| «Подтвердить передачу» | Отправитель, получатель-покупатель, NFT, цена и время | **Заявление продавца** |
| Служебная передача NFT | Отправитель, получатель, подарок и время | `unique_gift` с `origin=transfer`, если Telegram передал событие боту |

Открытие профиля бота без отправки сообщения Telegram не сообщает через Bot API. Поэтому «посещения» означают запуски `/start`, а не все открытия профиля. Журнал не читает историю всех пользователей: видны действия в этом боте и события из доступных ему подключённых чатов. Обновление обычного подарка до NFT и пересланная карточка подарка не считаются передачей.

События Telegram отмечаются отдельно от заявлений участников. Бот не угадывает отправителя или получателя, если не может определить их по сообщению. Служебная запись говорит о событии передачи, а не о текущем владельце NFT или гарантии оплаты.

Исторические заявления о передаче, получении подарка и оплате из прежних версий сохраняются в журнале; соответствующие дополнительные кнопки на карточке больше не показываются.

Тексты обычных переписок, токен и сам промокод в журнал не записываются. Участникам сообщается, что запуски бота и действия с офферами сохраняются. Журналы доступны только активированному администратору этого экземпляра бота.

## Офферы без ручного ввода ID

Пусть собеседник сначала напишет тебе сообщение. Отправь команду со своего подключённого аккаунта в личный чат с владельцем подарка:

```text
.buy ССЫЛКА_НА_НФТ ЦЕНА ВАЛЮТА ЯЗЫК

.buy https://t.me/nft/DurovsCap-1234 500 stars
.buy https://t.me/nft/DurovsCap-1234 10 gram en
.buy https://t.me/nft/CupidCharm-15484 8900 stars ru
```

Валюты: `stars / gram`. Языки: `ru / en / zh / ar`, последний аргумент необязателен. Цена положительная: Stars — целое число, Gram — до 9 знаков после точки. `gram` сохраняется как ярлык цены, без подключения кошелька.

После успешной отправки карточки бот удаляет только исходную команду `.buy`. При ошибке или неопределённом результате отправки команда остаётся. Ошибка удаления не отменяет уже созданный оффер. Если право удаления не включено, бот один раз сообщает об этом владельцу в личке. Приветствие содержит только инструкции создания: команды последнего оффера там не показываются.

Временная ошибка удаления теперь сохраняет задачу в SQLite: повтор выполняется минимум через 30 секунд, в том числе после перезапуска. Карточка повторно не отправляется. Бот обновляет сведения о правах при обращении к подключению, если последняя проверка была больше минуты назад. Удаление прекращается через 48 часов после исходной команды. Обновление базы не ставит старые команды в очередь удаления.

Повреждённые и неполные ответы API обрабатываются без падения и повторной отправки карточки с неизвестным результатом. Ограничение скорости соблюдает полный `retry_after` Telegram. Постоянный отказ в ответе одному пользователю пропускает только соответствующее обновление, позволяя другим чатам продолжить работу; временный сбой сохраняет обновление для повторной обработки.

При отказе отправки владелец получает точный код и ответ Telegram. `PEER_FLOOD` подтверждает отказ в конкретном запросе. Он не доказывает запрет на все сообщения аккаунта и не позволяет точно определить причину. Проверить ограничения можно через [@SpamBot](https://t.me/SpamBot). Бот не повторяет автоматически отправку после `PEER_FLOOD`, не удаляет команду и не помечает оффер доставленным. Он не заменяет отказавшую отправку редактированием команды. См. [объяснение разработчика TDLib](https://github.com/tdlib/td/issues/797) и [официальную справку Telegram](https://telegram.org/faq_spam).

Автоматические редактирования после `PEER_FLOOD` приостанавливаются: пауза конкретного подключения и чата сохраняется в SQLite. Отказ на одной карточке приостанавливает остальные карточки этого чата в той же очереди; другие чаты продолжают работать. Уже доставленные офферы и их статусы сохраняются, карточки повторно не отправляются. При `429` редактирование откладывается как минимум на весь срок `retry_after`, включая перезапуск.

Версия 1.6.2 исправляет слишком жёсткую паузу 1.6.1: для восстановления старой карточки больше не требуется отправка нового оффера. По нажатию её кнопки бот проверяет участника, роль, допустимость действия и идентификатор доставленной карточки. Он синхронизирует эту же карточку с сохранённым состоянием; только после подтверждения API или ответа «message is not modified» разрешаются новое действие и автообновления этого чата. Если прежнее нажатие уже было записано, карточка лишь восстанавливает отображение, без повторной записи в журнале. При отказе, неопределённой сети или неверном идентификаторе ответа пауза остаётся и новое действие не записывается. Активный срок `retry_after` соблюдается перед запросом.

Уведомление показывает, видел ли бот входящее сообщение в этом чате за последние 24 часа. Сохраняется только его время, без текста и вложений. Если бот не видел входящих, он не делает вывод, что их не было до подключения. [Право `can_reply`](https://core.telegram.org/bots/api#businessbotrights) требует входящего за последние 24 часа. Это условие отдельно от `PEER_FLOOD`, его нарушение не объявляется доказанной причиной ошибки. Исходящая команда, редактирование и нажатие кнопки не обновляют время входящего.

Успешная новая `.buy` также возобновляет автоматические обновления прежних карточек того же чата. Входящее сообщение, ожидание, перезапуск и неудачная или неопределённая доставка сами по себе не снимают паузу. Восстановление по кнопке касается только уже доставленного оффера. Обычные сообщения и отказавшие команды не превращаются в новые офферы редактированием. Обновление исправляет восстановление разрешённой работы, но не снимает серверное ограничение Telegram.

```text
.status
.cancel
.help
```

`.status` показывает последний оффер в текущем чате. `.cancel` отменяет последний оффер до подтверждения передачи или прежнего заявления о получении оплаты. Ответы и подсказки приходят владельцу в личку с ботом. Команды в деловом чате выполняются только от владельца соответствующего подключения; собеседник не сможет создать предложение от его имени.

До принятия на карточке только две inline-кнопки: «Отклонить» и «Принять». После принятия — «Передать подарок» и «Подтвердить передачу», каждая отдельной строкой. Первая открывает меню подарков для покупателя по ссылке `tg://send_gift?to=USERNAME` из референса. Username берётся из данных самого покупателя; если его нет, ссылка использует ID этого покупателя автоматически. Получатель не задаётся отдельной настройкой. Владелец выбирает и передаёт подарок вручную. Вторая кнопка доступна только продавцу после принятия, записывает подтверждение передачи и закрывает оффер. После подтверждения, отказа, отмены или истечения срока inline-кнопок нет. Повторное нажатие не создаёт повторной записи.

Отдельные inline-кнопки «Показать подарок», профиля, оплаты, получения и отмены убраны. Превью NFT снова включено: явно задана ссылка именно на NFT, большое изображение показывается над текстом. Внутри штатного превью Telegram может добавить собственную кнопку просмотра — она не является inline-кнопкой бота. Повторяющийся текст про расчёт между участниками и журнал не выводится в карточке и приветствии.

Новая карточка начинается с «Пользователь предлагает Вам», выводит фактическую цену жирным и название конкретного подарка. Вместо абсолютной даты UTC показывается оставшийся срок, например «Предложение действует ещё 6 ч. 0 мин..». При нестандартном сроке или позднем обновлении число часов соответствует данным оффера. Время обновляется раз в минуту через редактирование уже отправленной карточки; по истечении срока действия кнопки решения исчезают.

Ссылка меню подарков проверена по [официальному исходному коду Telegram для Android](https://github.com/DrKLO/Telegram/blob/master/TMessagesProj/src/main/java/org/telegram/ui/LaunchActivity.java). Поддержка этой схемы зависит от клиента Telegram. Она не выполняет автоматическую передачу и не проверяет оплату.

Каждая кнопка проверяется по данным Telegram и исходной карточке. Внутренние идентификаторы остаются в базе для этих проверок, но не требуют настройки и не отображаются кодами в карточках.

## Оплата и внешний вид

**Приём платежей, резервирование денег, выплаты и автоматическая передача NFT не подключены.** «Подтвердить передачу» фиксирует только заявление продавца о передаче и не подтверждает оплату или получение NFT покупателем. Нажатие «Принять» не блокирует деньги и не запускает платёж. Бот не выдаёт себя за официальную гарантийную систему Telegram.

Превью `https://t.me/nft/...` формирует Telegram: крупная картинка показывается над текстом, если превью доступно. Фон чата зависит от темы приложения. Тексты находятся в `gift_offer/views.py`, админские журналы — в `gift_offer/admin.py`, общие иконки — в `gift_offer/ui.py`.

| Назначение | Custom emoji ID |
| --- | --- |
| Цена в Stars | `5848259999763011021` |
| Цена в Gram | `5377620962390857342` |
| Отклонение и отмена | `5893081007153746175` |
| Подтверждение и переход | `5409029658794537988` |

Цены используют HTML `tg-emoji`, кнопки — `icon_custom_emoji_id`. Telegram ограничивает доступность кастомных эмодзи: Premium владельца бота сам по себе не даёт эту возможность в сообщениях от имени бизнес-аккаунта. Если API явно отказывает из-за кастомных эмодзи, бот один раз повторяет запрос с обычными значками и сохраняет все кнопки. При сетевой неопределённости отправка не повторяется. Подробности: [иконки кнопок](https://core.telegram.org/bots/api#inlinekeyboardbutton), [эмодзи в тексте](https://core.telegram.org/bots/api#html-style), [удаление команд](https://core.telegram.org/bots/api#deletebusinessmessages).

## Необязательные настройки

| Переменная | По умолчанию |
| --- | --- |
| `BOT_NAME` | `Gift Offer`, подпись в карточках |
| `DEFAULT_LANGUAGE` | `ru` |
| `OFFER_TTL_SECONDS` | `21600`, 6 часов на первоначальное решение |
| `CREATE_COOLDOWN_SECONDS` | `3` секунды |
| `DB_PATH` | `data/offers.sqlite3` |
| `PORT` | `3000`; `0` отключает служебный HTTP-сервер |
| `ADMIN_PROMO` | `/ClezzyKryt`; можно изменить команду активации без ввода ID |

Для хостинга с Python основной файл — `bot.py`, команда запуска — `python bot.py`. Служебный сервер слушает `0.0.0.0:PORT`, состояние процесса доступно на `/healthz`. Используется long polling; нужен исходящий HTTPS к `api.telegram.org`, домен и webhook для сообщений не требуются.

На Bothost включи **«Использовать собственный Dockerfile»**, главный файл укажи `bot.py`, ветку — `main`. Dockerfile закрепляет Python 3.12 и запускает `python -u bot.py`. Каталог `/app` на Bothost монтируется при запуске; образ использует пользователя по умолчанию, чтобы запись в примонтированный `/app/data` не зависела от прав пользователя, созданного при сборке.

В поле токена Bothost вставь токен этого бота. Код читает `BOT_TOKEN`, также поддерживает `API_TOKEN` и `TELEGRAM_BOT_TOKEN`. Если используется несколько имён, приоритет у `BOT_TOKEN`. Путь базы можно задать как `DB_PATH=/app/data/offers.sqlite3`; альтернативно учитывается `DATA_DIR`. Чтобы оставить существующие журналы и админ-доступ, сохраняй прежнюю базу и путь к ней.

Домен для сообщений не нужен. Если оставляешь домен включённым, укажи внутренний порт `3000` и `PORT=3000`. HTTP-сервер запускается до подключения к Telegram. `GET /health` и `/` проверяют, что процесс жив; `/healthz` и `/readyz` возвращают 503, пока Telegram не подключён или polling давно не выполнялся. Временная ошибка сети при старте вызывает повторное подключение, а не завершение процесса. Регистрация меню команд не блокирует работу бота.

Если у бота уже настроен webhook, он автоматически отключается перед запуском polling. Ожидающие обновления сохраняются: используется `deleteWebhook` с `drop_pending_updates=false`. Если другой сервис снова настроит webhook, останови его перед перезапуском этого проекта. `WEBHOOK_URL` от платформы не переключает этот проект в webhook. Краткий конфликт двух процессов при обновлении повторяется до шести раз; постоянный конфликт завершается с пояснением в логах.

## Обновление старой версии

Останови бота, замени исходники новой версией, сохрани свой `.env` и папку `data`, затем запусти `python bot.py`. Существующие офферы сохранятся. Старые заявления о передаче импортируются в журнал один раз. Новые посещения `/start` и служебные события Telegram начинают записываться после обновления — прошлые открытия профиля восстановить нельзя. Перезапуск не сбрасывает админ-доступ.

При первом запуске версии 1.6.0 существующие доступные карточки ставятся в очередь редактирования, чтобы обновить текст, превью и ссылку передачи. Их статусы, сообщения и записи журнала сохраняются. Офферы повторно не отправляются; следующие перезапуски не запускают такое обновление заново.

Храни папку `data` на постоянном диске. Запускай один экземпляр на один токен. Повторная доставка одной команды или одного события не создаёт дубликат в журнале. При обрыве сети во время отправки оффер не пересылается автоматически: сообщение могло уже появиться в чате.

## Проверка

```bash
python -m unittest discover -s tests -v
```

128 автоматических тестов прошли с имитацией Telegram API: офферы, удаление исходной команды только после доставки и восстановление удаления после перезапуска, обновление прав, иконки и обычные значки при отказе API, роли, сроки, сеть, четыре языка, активация админки, защита журналов, посещения, отправители/получатели NFT, обновление старой базы, переключение с webhook на polling без очистки очереди, запуск HTTP до Telegram и восстановление при временном конфликте. Полный сценарий через настоящий HTTP-обработчик бота проверяет сериализацию запросов, отказ в эмодзи, отправку и удаление, принятие и подтверждение передачи Stars, отклонение Gram и активацию админки. Проверяются фактическая цена/срок, уменьшение времени и истечение срока без новых сообщений, превью NFT, адресация меню подарков покупателю, доступ к подтверждению только продавцу после принятия, защита от повторных записей, отсутствие заявления об оплате и однократное обновление старых карточек. Проверены HTTP-отказ PEER_FLOOD без повторов и редактирования команды, остановка редактирований всего затронутого чата с сохранением при перезапуске, работа остальных чатов при заполненной очереди, различение входящих и исходящих, отсутствие ложных действий на приостановленных карточках, возобновление после подтверждённой новой доставки и полный срок retry_after после последнего отказа с сохранением при перезапуске. Проверено восстановление старой карточки её кнопкой без новой отправки, включая перезапуск и сериализацию HTTP-запросов, отсутствие повторного журналирования сохранённых действий, сохранение паузы при отказе, неопределённой сети и неверном идентификаторе ответа, запрет обновления чужой ролью и соблюдение активного retry_after. Реальный запуск на Bothost с токеном пользователя не выполнялся.
