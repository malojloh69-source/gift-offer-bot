# Gift Offer Bot

Telegram-бот для автоматизации чатов и предложений покупки NFT-подарков: `.buy`, принятие и отклонение, четыре языка, журнал посещений и передач. После успешной отправки карточки исходная команда `.buy` удаляется. Админ-панель активируется командой `/ClezzyKryt` с подключённого аккаунта. Ручной ввод Telegram ID не нужен.

В версии 1.6.0 карточка начинается с «Пользователь предлагает Вам», показывает действительную цену и подарок, затем оставшееся время: «Предложение действует ещё 6 ч. 0 мин..» при стандартном сроке. Сумма выделена жирным; цена и время берутся из оффера. Время обновляется раз в минуту редактированием уже доставленной карточки, без новых сообщений.

Превью NFT восстановлено над текстом. Telegram сам добавляет кнопку просмотра внутри превью; отдельной inline-кнопки «Показать подарок» нет. До принятия остаются «Отклонить» и «Принять», после — «Передать подарок» и «Подтвердить передачу». Первая использует ссылку `tg://send_gift?to=USERNAME` покупателя оффера и открывает меню подарков в Telegram для Android; без username получатель определяется автоматически по его ID. Вторая записывает заявление продавца о передаче и закрывает оффер. Оплата этим действием не подтверждается. Дополнительные inline-кнопки и повторяющийся текст про расчёт и журнал убраны. Ранее отправленные карточки обновляются при запуске новой версии.

## Запуск на Bothost

Исходники лежат в корне репозитория. Создай или обнови Python-проект на [Bothost](https://bothost.ru/):

| Настройка | Значение |
| --- | --- |
| Git-репозиторий | Ссылка на этот репозиторий |
| Ветка | `main` |
| Главный файл | `bot.py` |
| Использовать собственный Dockerfile | **Включить** |
| Токен бота | Токен от @BotFather, в поле токена Bothost или в `BOT_TOKEN` |
| Домен | Для polling не требуется |
| Путь базы | `DB_PATH=/app/data/offers.sqlite3`, либо прежний путь существующей базы |

После сохранения настроек выполни **новый деплой**. Для домена укажи внутренний порт `3000` и `PORT=3000`. Бот сам снимает существующий webhook, сохраняя ожидающие обновления. Запускай один экземпляр на токен.

Этот репозиторий приватный. В Bothost сначала подключи его через раздел «Git репозитории»: HTTPS, ветка `main`, username `x-access-token`, GitHub fine-grained token с доступом только к этому репозиторию и правом `Contents: Read-only`. Токен вводится только в Bothost. [Инструкция подключения](https://bothost.ru/docs/git-repository-access).

В логах запуска будут адрес HTTP-сервера и строка `@имя_бота started`. `GET /health` доступен во время подключения к Telegram; `/readyz` показывает готовность polling. Временные сетевые ошибки повторяются автоматически. При длительном конфликте, неверном токене или проблеме с SQLite причина появляется в логах.

При отказе отправки бот показывает владельцу точный код и ответ Telegram. `PEER_FLOOD` означает ограничение Telegram на исходящие сообщения подключённого аккаунта этому собеседнику; дополнительные права бота его не снимают. Проверь ограничения через [@SpamBot](https://t.me/SpamBot). Такой оффер не отправлен, исходная команда остаётся, автоматических повторов отправки нет. См. [объяснение разработчика TDLib](https://github.com/tdlib/td/issues/797) и [официальную справку Telegram](https://telegram.org/faq_spam).

В @BotFather включи Secretary Mode / Business Mode. Подключи бота к аккаунту Telegram через **«Автоматизацию чатов»** и разреши ответы и **удаление сообщений** в нужных чатах. Для удаления команды, отправленной владельцем аккаунта, требуется право `can_delete_all_messages`; право только на удаление сообщений самого бота не подходит. Оффер отправляется первым, команда удаляется после успешной доставки. Если доставка не удалась, команда остаётся в чате.

В версии 1.4.0 удаление команды восстанавливается после временной ошибки сети и перезапуска: очередь хранится в SQLite, повторяется только удаление, карточка повторно не отправляется. Права подключения обновляются не реже раза в минуту при обращении к нему. Команды старше 48 часов и исторические команды при обновлении базы не удаляются. Повреждённый ответ API обрабатывается как неопределённый результат, задержка `retry_after` соблюдается полностью. Отказ в ответе одному пользователю не блокирует обработку остальных чатов.

Отправь боту `/start`, затем `/ClezzyKryt` с того же подключённого аккаунта. Администратор закрепляется за первым подключённым владельцем, успешно активировавшим панель.

База, журналы и админ-доступ хранятся в `data`. При обновлении сохраняй эту папку. Токен и `.env` задаются на сервере и не загружаются в GitHub.

## Локальный запуск

Нужен Python 3.11+. Сторонних зависимостей нет.

```bash
cp .env.example .env
# Впиши свой BOT_TOKEN в .env
python bot.py --check
python bot.py
```

```text
.buy https://t.me/nft/CupidCharm-15484 8900 stars ru
.status
.cancel
```

В приветствии показаны только инструкции создания оффера. `.status` и `.cancel` по-прежнему работают в подключённом чате.

Цена оформлена кастомными эмодзи Stars `5848259999763011021` и Gram `5377620962390857342`. Кнопки отклонения и отмены используют `5893081007153746175`; подтверждения и переходы — `5409029658794537988`. Эти же иконки используются в админ-панели. [Telegram ограничивает использование кастомных эмодзи](https://core.telegram.org/bots/api#inlinekeyboardbutton), в том числе в сообщениях от имени подключённого аккаунта. Если API явно отказывает в их использовании, бот один раз отправляет ту же карточку с обычными значками, сохраняя все действия. При неопределённом сетевом результате карточка не дублируется.

Журналы доступны через `/admin`, `/logs`, `/visits`, `/transfers`. Посещения означают `/start`; заявления участников о передаче отмечаются отдельно от доступных служебных событий Telegram. Приём оплаты, резервирование денег и автоматическая передача NFT не подключены.

## Проверки

```bash
python -m unittest discover -s tests -v
```

106 автоматических тестов прошли, включая полный сценарий через HTTP-обработчик с имитацией Telegram: создание, отказ в кастомных эмодзи, удаление команды, принятие и подтверждение передачи Stars, отклонение Gram и админ-панель. Проверяются реальные цена/срок, обновление времени без новых сообщений, адресация подарка покупателю, права на подтверждение, повторные нажатия, восстановление после перезапуска и обновление прежних карточек. Реальный запуск с токеном пользователя на Bothost не выполнялся.
